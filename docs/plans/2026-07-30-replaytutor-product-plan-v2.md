# ReplayTutor 产品规划 v2：基于开源生态的 AI 共画式交易训练平台

状态：Approved for planning
日期：2026-07-30
产品形态：云端桌面 Web SaaS

## 一、市场判断与差异化

市场已经验证了“历史回放 + 模拟交易 + 日志 + AI 教练”的需求：

| 产品 | 可借鉴能力 | 留给我们的空间 |
|---|---|---|
| [TradingView Bar Replay](https://www.tradingview.com/support/solutions/43000691889-learn-to-trade-on-historical-data/) | 专业图表、历史回放、模拟交易 | 不是围绕策略教学和逐笔纪律审查设计 |
| [FX Replay](https://fxreplay.com/backtest) | 图表下单、回放、日志、Mentor AI、绩效分析 | AI 更偏行为反馈，公开页面未体现人机共画审计 |
| [TradeZella](https://www.tradezella.com/) | Playbook、回放、日志、AI 会话总结 | 重心偏交易日志和真实成交导入 |
| [TraderSync](https://tradersync.com/pricing/) | 交易计划、跨市场回放、Cypher AI 教练 | 面向已有交易记录的成熟交易者 |
| [Praxys Labs](https://praxyslabs.com/en) | 策略规则化、历史训练、逐笔评分、弱项专项训练 | 是最接近的直接竞品，但公开形态仍偏规则评分 |
| [Signum](https://www.signum.trading/) | AI 看图、结构化课程、能力等级 | 更偏实时图表问答和课程 |
| [Truefin](https://truefin.org/) / [Trading Game](https://tradinggame.com/) | 新手课程、模拟训练、AI 复盘、成长体系 | 交互更轻，专业回放和证据审计深度有限 |

ReplayTutor 的定位应收紧为：

> 不是“带聊天框的 TradingView”，而是“用户先表达图表判断，AI 在同一张图上协作、质疑和复盘的策略训练系统”。

核心差异化：

1. 用户先画、AI 后回应，避免 AI 替用户思考。
2. 每笔交易先提交计划，再比较计划质量、执行偏差和最终结果。
3. AI 标注是可接受、修改、拒绝、追问和重放的结构化证据。
4. 回放中严格禁止 AI 读取未来 K 线，结束后才切换到事后视角。
5. 盈利不等于正确，亏损不等于错误；评分以过程和纪律为主。

## 二、产品形态与完整体验

产品采用“策略训练学院 + TradingView 式工作台 + 证据复盘中心”。

一级空间：

- **首次体验/今日训练**：固定震撼 Demo、推荐练习、近期弱项。
- **策略学院**：趋势回调、突破回踩、区间反转三套官方策略。
- **回放工作台**：K 线、画图、模拟订单、计划卡、回放和 AI Tutor。
- **复盘中心**：单笔、会话、周期报告及图表证据回跳。
- **我的 Playbook**：将官方策略复制并逐步修改为个人策略。

首次体验控制在 5–8 分钟：

```text
固定真实 BTC 片段
→ 用户标趋势和关键位
→ AI 用独立图层补画并追问
→ 用户拖出入场、止损、目标
→ 填写强制计划卡
→ 回放后续 K 线并模拟交易
→ AI 叠加“用户判断 / 策略标准 / 实际走势”
→ 播放证据化复盘故事
```

训练开始前选择 AI 协作强度：

- **全自动**：AI 主动画结构、关键位、情景路径；用于示范和事后复盘。
- **半自动，默认**：用户先画，AI 对照、补充和提问；用于学习。
- **手动**：AI 只在用户请求时介入；用于考试和自由训练。

训练状态固定为：环境判断 → 机会识别 → 计划制定 → 下单 → 持仓管理 → 退出说明 → 事后复盘。

## 三、AI 共画与策略审查

AI 不能直接输出不可编辑的图片。它必须通过白名单图形指令创建：

- 趋势线、水平位、价格区域。
- 高低点、结构突破、回踩点。
- 入场、止损、目标和失效区域。
- 场景路径箭头、文字说明和证据引用。

每个标注保存：

- 创建者：用户、AI 或官方策略。
- 依据：K 线范围、指标、计划字段和策略规则。
- 性质：确定性观察或 AI 推断。
- 置信度及未知项。
- 状态：提议、接受、拒绝、用户修改。
- 创建时的 `frame_id` 和 `visible_at`。

半自动模式的互动节奏：

1. 用户提交环境标注后，AI 显示一致点、冲突点和遗漏点。
2. 用户圈出候选入场区后，AI 将未满足的策略规则挂到对应 K 线上。
3. 用户提交计划卡前，AI 检查失效位、风险收益和仓位一致性。
4. 持仓中仅在规则触发、结构失效或用户主动提问时介入。
5. 用户先说明退出原因，AI 再展示原计划、实际执行和替代管理路径。

复盘分别评价：

- 环境是否适合所选策略。
- 用户是否正确识别形态。
- 计划是否完整且内部一致。
- 入场、止损、仓位和退出是否符合计划。
- 盈亏中有多少来自执行质量、市场随机性或计划本身的问题。

能力档案使用环境识别、形态识别、计划质量、风险管理、执行纪律、复盘反思六个维度；每项显示证据等级和样本数，不生成误导性的单一总分。

## 四、开源复用方案

采用“保留现有 ReplayTutor 骨架，选择性吸收”的路线。

### 直接采用

- **[KLineChart](https://github.com/klinecharts/KLineChart)**：Apache 2.0，已有指标、画线和扩展 API；继续作为主图表内核。
- **[KLineChart Pro](https://github.com/klinecharts/pro)**：Apache 2.0，仅借鉴工具栏、指标选择和图表工作台组合。
- **[XState](https://github.com/statelyai/xstate)**：MIT，用于训练阶段、AI 模式和中断恢复状态机。
- **[json-rules-engine](https://github.com/CacheControl/json-rules-engine)**：ISC，用于官方策略中可以确定性计算的规则。
- 继续复用现有 Binance 公共行情、Parquet/DuckDB、K 线聚合、标注适配器和反前视约束。

### 拆解和移植思想

- **[PivBO](https://github.com/mbelgin/PivBO)**：MIT，已有逐 K 回放、市场/限价单、止损、分批退出、R 倍数、保存恢复和画图。重点参考其回放操作流、快捷键和训练会话模型；不复制其 Flask + 单文件 HTML + JSON 存储架构。
- **[QuantReplay](https://github.com/Quod-Financial/quantreplay)**：Apache 2.0，保留为未来 tick、订单簿、FIX 和多市场撮合候选。
- **[LEAN](https://github.com/QuantConnect/Lean)**：Apache 2.0，参考事件驱动、市场规则和确定性测试设计；MVP 不引入其 C# 运行时。
- **[NautilusTrader](https://github.com/nautechsystems/nautilus_trader)**：LGPL-3.0，未来需要高性能 tick/L2 回放时再做独立服务评估。

### 只借鉴产品，不复制代码

- **[Tradenza](https://github.com/HonzaPrikryl/tradenza)**：AGPL-3.0。借鉴策略检查表、计划遵守度、纪律热力图、交易详情侧栏和复盘信息架构。
- **[TradeNote](https://github.com/Eleven-Trading/TradeNote)**：GPL-3.0。借鉴导入、标签和日志组织。
- 若 ReplayTutor 维持闭源商业 SaaS，不直接合并 AGPL/GPL 代码；商业使用前建立依赖清单、许可证扫描、NOTICE 和 SBOM。此处是工程筛选，不代替正式法律意见。

## 五、MVP 系统范围与接口

MVP 固定为：

- 云端桌面 Web SaaS。
- BTC、ETH 现货，不做杠杆和裸空。
- 1m 原始数据，服务端派生 5m、15m、1h、4h。
- 三套官方价格行为策略。
- 市价、限价、止损、目标和分批退出。
- 固定引导 Demo、随机训练、学习模式和考试模式。
- 云端账号、训练历史、能力档案和 AI 模型网关。

核心接口：

- `StrategyTemplate`：策略版本、环境、形态、触发、失效、风险、管理、退出和可计算规则。
- `TrainingSession`：品种、数据快照、策略版本、AI 模式、训练阶段、状态和当前可见时间。
- `TradePlan`：方向、入场理由、入场区、失效条件、止损、目标、风险金额和退出计划。
- `ReplayFrame`：服务端签发的可见行情、订单、持仓、revision、`frame_id` 和 `visible_at`。
- `ChartAnnotation`：几何数据、创建者、证据、规则引用、置信度和接受状态。
- `AIInteraction`：触发阶段、问题、图形指令、用户回应和运行状态。
- `ReviewArtifact`：计划评价、执行偏差、能力维度、证据引用、复盘图层和下一次训练。

确定性内核负责时间、撮合、费用、盈亏、MFE/MAE 和规则计算；AI 只负责追问、推断、解释和生成受控标注。

## 六、实施顺序与验收

### 阶段 0：开源吸收验证

- 将现有工作台与 PivBO 的回放流程逐项对照。
- 验证 KLineChart 的用户/AI/策略三层标注、编辑和序列化。
- 用 XState 建立完整训练状态机。
- 用规则引擎表达一套最小“突破回踩”策略。
- 建立第三方许可证、版本和 NOTICE 清单。

### 阶段 1：首次震撼 Demo

交付固定 BTC 真实片段、用户先画、AI 补画、计划卡、模拟交易和三层复盘。确保首次完整体验在 5–8 分钟内完成。

### 阶段 2：自由训练 MVP

加入 BTC/ETH 随机片段、三套策略、三种 AI 模式、会话恢复、能力雷达和个人 Playbook。

### 阶段 3：学习闭环

加入弱项专项训练、考试解锁、周期报告、更多片段和订阅额度。真实成交导入、策略市场和高精度 tick 回放延后。

验收场景：

- 回放 UI、策略引擎和 AI 均无法读取 `visible_at` 之后的数据。
- 用户、AI、策略三套图层可以隐藏、比较、编辑和重放。
- AI 标注必须引用有效证据；无效引用不得进入正式报告。
- 同一快照和操作序列产生一致的订单、成交和指标。
- 盈利但违反计划的交易不能获得高纪律评价。
- 亏损但执行有效计划的交易不能被简单判错。
- 手动模式下 AI 不主动标注；全自动标注不计入考试成绩。
- AI 超时或失败不阻塞回放、画图和模拟交易。
- AGPL/GPL 代码不得进入闭源构建产物。
- 首次体验至少完成一次用户画图、一次 AI 图形互动和一次证据复盘。
